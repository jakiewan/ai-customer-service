# GlobalCare Web 售后 Case 智能受理 Agent MVP

## 目标

面向手机售后网页聊天场景，构建一个可审计、可恢复、带政策引用的 Agent 服务。Agent 负责理解问题、回答 FAQ/故障排查、查询维修进度、收集受理字段并生成 Case Draft；正式 Case 和 Work Order 仍由既有 Java 下游流程处理。

## 用户与数据边界

- 渠道：Vue 3 网页文字聊天，不做语音、图片和电话。
- 市场：CN、MY；哪个国家购买，就使用哪个国家的售后政策和流程，不做跨国售后判断。
- 数据：全部为模拟/脱敏数据；第一版使用 `X-Demo-Token`，不做真实登录。
- 模型：MiniMax-M3；默认支持离线规则/假模型以便测试，真实调用由配置开关启用。

## 核心用例

1. 故障咨询：识别问题并给出政策允许的可操作排查步骤，不创建草稿。
2. 维修进度：根据订单号或序列号调用只读业务工具，直接返回状态，不创建草稿。
3. 申请维修：补齐必要字段，检索订单所属市场的政策，查询设备/订单事实，校验后创建或复用同一会话的 Case Draft。
4. 无证据或超范围：不做确定性承诺，返回 `human_required` 提示，不自动转人工。

## 非功能要求

- LangGraph 显式状态图，限制最大步骤和工具轮次，支持会话 checkpoint。
- LangChain 负责模型、结构化输出、Prompt、RAG 和工具适配。
- PostgreSQL + pgvector 保存政策向量、会话、草稿和审计信息。
- FastMCP 只暴露查询类工具；正式 Case/Work Order 写操作不得暴露给模型。
- FastAPI 提供 Vue 联调所需 REST + SSE 契约。
- 测试覆盖意图路由、市场过滤、状态流转、草稿幂等、无证据拒答和 HTTP 契约。

## 验收标准

- AC-001：FAQ/故障排查使用政策证据并返回可操作建议。
- AC-002：政策检索严格按订单所属市场过滤。
- AC-003：LangGraph 能按意图进入 FAQ、进度查询或 Case Draft 分支。
- AC-004：业务查询通过 MCP 适配器并规范化工具错误。
- AC-005：Agent 只能生成结构化 Case Draft，不创建正式 Case/Work Order。
- AC-006：字段、证据和业务事实校验通过后才能保存草稿。
- AC-007：草稿为 `DRAFT_CREATED`，Agent 侧流程结束。
- AC-008：同一会话和同一业务指纹重复请求返回既有草稿。
- AC-009：无可靠证据时不做确定性承诺，返回 `human_required`。
- AC-010：模型尝试写工具时被权限门禁拦截。
- AC-011：超过最大图步骤或预算时优雅停止。
- AC-012：可查询会话、工具、政策和草稿审计轨迹。
